# State of War Warmonger: audit (2026-11-08)

Warmonger lives next to the base game in the same Steam depot (`.../depot_748041/State of War Warmonger`, own exe + `Data`). Goal: one game,
a toggle on the campaign map between the two campaigns (no separate Warmonger build). Everything below was measured on the install; the exe
facts come from disassembly of `State of War Warmonger.exe` (VA = file offset + section delta, image base 0x400000).

## It is not only missions
Same engine (a ~136 KB smaller, older build; source path `div__english__warmonger_`), same formats (`opensow check` on the Warmonger dir: 806 ok, 0 failed),
but different data in these places:

| Area | Base | Warmonger |

## Campaign map (`CMenuBriefing`, text function `0x43d250`)
- Still **22 lands** on the same world map (same land sprites). Land L is mission `M<L>` as in the base game.
- Not in the original: the Warmonger campaign map is tinted red (red and green channels of `Briefing2.srf`, `Briefing.srf`, the small-screen `mB` globe and the toggle bar swapped, `lands::campaign_tint`) so it is told apart from the base game's green map at a glance; the land sprites keep their colours.
- Only 11 lands have text; table `0x43d6e8` (22 bytes, land -> case 0..10, 11 = "No data available"): lands **1, 2, 3, 4, 6, 7, 11, 12, 15, 20, 22** -> cases 0..10. All other lands stay locked/"No data available".
- Territories by case: 1 Crystal Brotherhood base (research 1000, difficulty 2), 2 small robot regiment, 3 Rogon convoy, 4 heavy turrets/45 min destroy all, 5 gold mines/hold 35 min, 6 hold 30 min then destroy both HQs, 7 take the base, 8 Golden Dale, 9 four HQs in 45 min, 10 islands/air forces, 11 Mr. Rahman (final).
- **Progress** (`CPassedLevels` `0x712724`, byte `+4+land`; `0x450b00` Pass, `0x450a70..` ctor, initial state at `0x450f3f`): initial lands **1, 2, 3** are 2 (open) (base: 1, 2, 9). `Pass(22)` = ending. Passing a land makes it 1, then: if land 15 passed -> land 22 opens; else if lands 1,2,3,4,6,7,11,12,20 are all passed -> land 15 opens; else the first still-locked land in the order **4, 6, 7, 11, 12, 20** opens.

## Mission rules
The mission-number global is `0x491360` (base `0x49a33c`). Both exes have **33** references, site for site in the same order, with the same comparison sets (win rule "destroy all" for 4/8/13/16/21/22 and the second test `0x421557` for 4/13/16/21/22, pods 3/8, countdown rewards 7/12/17, M07 HQ Advancer, hints 1/6, M01 carryalls, tutorial 0), so the sim's per-number rules (`sim/mission.rs`) apply to Warmonger as they are. The Warmonger objectives fit them (M03 convoy, M04 destroy-all in 45 min, M07 30 min then reinforcements, M22 destroy-all final). The **only** differing mission comparison is the radar frame (`0x44eb11`, `0x44f5d9`; base `0x454631`, `0x455059`): the small 76x76 frame is used for Warmonger missions **1, 4, 6, 11, 20** (base 1, 2, 6, 9, 11, 12, 14, 16, 20); the other apparent differences in a byte diff are code layout (diffed with a capstone scan of every reference). The base game's "air stock", tier flags and countdown values come from the level header, which the loader already handles.

The radar picture: Warmonger's exe loads the loose `Data\Sprites2\extras\radar2.tsp` (`0x424779`, array `0x53e510`) besides the base `extras\radar` and draws `radar2[k]` (`0x44ebb4`), `k` from the byte table `0x44efc0` -> jump table `0x44ef90` over `mission - 1`: missions 1, 2, 3, 4, 6, 7, 11, 12, 15, 20, 22 (Warmonger's eleven) get frames 0..10 in order, any other number falls through with 0. The 64x64 frames are exactly the small-radar missions 1, 4, 6, 11, 20. With the radar off (`[0x6a7798]`) it draws the base `radar` plate like the base game. OpenSOW: same (`hud::SMALL_RADAR_WARMONGER`, `hud::radar2_frame`, `Assets::warmonger_radar`; tests `warmonger_uses_its_own_small_radar_list_and_pictures`, `warmongers_radar_pictures_fit_its_small_radar_list`).

## Already works
All 11 missions load and run headless in the current build when `OPENSOW_GAME_DIR` points at the Warmonger folder (`--play Mxx --ticks 600 --report --screenshot`, renders look right), so the sim, renderer, map/til/edt parsers and sprites need no changes.

## Implemented (2026-11-08)
Decision: Warmonger is a standalone expansion that adds no assets, so the port uses the base game's HUD, menus, sprites, sounds and fonts and takes only **mission data and texts** from Warmonger.

**Differs from the exe:** Warmonger is its own program with its own install; OpenSOW plays it as a second campaign of one game, switched on the campaign map. Its own menu skin, HUD frame (`menu\ingame.ps6`), intro `mI` and map movies `mA`/`mB` are not used (only its ending `mO`); the base game's are shown instead.
**Differs from the exe:** Warmonger's exe is English only; OpenSOW shows its land texts in English (from the exe) and, in English, its own mission hints ("In-game strings" below), but every other in-game string from the chosen base-game language file. In other languages the hints are the base game's translation, whose fighter hint names "A.A. turrets on the island", which fits only the base game's M01.
- `GameDir` (`formats/src/lib.rs`): optional `warmonger` root + `edition`. `resolve` redirects only `Data\Levels\M01..M22.*` and the ending movie `mO` to Warmonger while the Warmonger edition is selected (never falls back to the base game's same-named mission); `*.net` skirmish maps are the base game's plus Warmonger's (always listed after the base maps; **Differs from the exe:** each exe lists only its own); `level_files()` is the edition-aware directory listing. The tutorial `M00`, the intro `mI`, `mA`/`mB` and everything else stay the base game's.
- Finding the install (`GameDir::is_warmonger_dir`: `Data\Levels\M01.*` and a `*warmonger*.exe`): `--warmonger DIR`, else `GameDir::locate` tries `OPENSOW_WARMONGER_DIR`, then the folder saved by the launcher (docs/launcher.md), then a sibling folder whose name contains "warmonger". There is no in-game path entry: a missing install shows an error box when the Warmonger label is clicked.
- Texts: `formats::warmonger::parse_texts` reads the 11 lands' four strings out of the exe at run time; lands outside `warmonger::LANDS` stay locked ("No data available").
- Progress: `PassedLevels::initial_warmonger` / `pass_warmonger` (exe `0x450f3f`, `0x450b00`); the statistics screen is the base game's code (`0x447dcc..0x447deb`: reload `player2.cfg`, `Pass([0x491360])`, write), so a mission continued from a save passes its land here too (test `a_warmonger_mission_won_after_loading_a_save_passes_its_land`); the progress file is `player.cfg` for the base game and `player2.cfg` for Warmonger (the exe's own name, `0x87f24`). **Differs from the exe:** **saves share the slots and flag their campaign** (each exe has its own `Savegame` folder): the extension after the stream's `Checksum` tag is `OpenSOW4` (level, edition byte, snapshot) for both campaigns; a stream without it (the original's) reads as the base game. Compatibility with saves of older builds is not a goal. Loading a slot selects its campaign first (an error message if Warmonger is not installed). The last edition is remembered in `edition.txt` of the user data folder (interactive runs only; not in the exe).
- Campaign map: two labels at the top (STATE OF WAR | WARMONGER) switch the edition; dev UNLOCK ALL opens only the 11 Warmonger lands. Headless: `--edition original|warmonger`, `--missing-warmonger`.
- Tests: synthetic overlay tests (`lib.rs`), `warmonger_missions_and_texts_load_through_the_edition_overlay` (real install), progress chain, lands texts and toggle, edition switch end to end. Quirk found: Warmonger M07 has two player turrets (kind 26, cells 68/69,45) on blocked cells.

## In-game strings (checked 2026-11-20)
Warmonger has no language file: each English string is a literal in its exe. Every string of `langEN.txt` that the base game draws during a mission was looked up in Warmonger's exe (exact match, then the nearest string for the rest):
- **Same text:** the 24 speech-event messages, the info box (labels and the unit/building description pages), "SATELLITE PROTECTION", "P A U S E", "Session Lost" and the in-game multiplayer lines.
- **Mission hints, different text:** the hint routines (`0x42f650` mission 1, `0x42fa30` mission 6) are the base game's `0x4303e0` / `0x430770` instruction for instruction (same conditions, boxes and offsets), but push three literals where the base game asks for strings 280, 280, 281: box 0x94 "Now increase tech-level in your factory." (`0x483f5c`, as 280), box 0xbc "Now increase tech-level of next unit in your factory." (`0x483f88`; the base game repeats 280 in this wider box) and box 0xc1 "Now use fighters to destroy enemy turrets." (`0x483fc0`; base 281 "... A.A. turrets on the island."). OpenSOW: `warmonger::parse_hints` reads the three lines from the exe and `play::hint_line` shows them for the Warmonger campaign in English (tests `parses_the_three_hint_lines_after_the_first_one`, `warmonger_hints_use_its_own_line_for_each_box`).
- **Countdown:** "Remaining time " (`0x483cf0`) instead of "Remaining Time"; no visible difference, the countdown is drawn uppercase.
- **Not in Warmonger's exe:** the game-speed readout "speed" (F3 / F4), the statistics and load/save labels and the menu strings (Warmonger's menu skin has them in its pictures). OpenSOW uses the base game's screens for both campaigns.
- Tutorial lines are reworded (e.g. "basic functions" for "basic features"); OpenSOW plays the base game's tutorial `M00` for both campaigns, so they are not used.
- Not in the base exe: a typed line "Yeah! Let's Finish him!" at `0x4261da` (a key-sequence cheat that adds credits; not traced further, not ported).
