# After a mission: banner and statistics screen

Code: `crates/opensow-game/src/results.rs` (`Results`), `crates/opensow-formats/src/endscreen.rs` (pure arithmetic), counters `World::stats` (sim.rs). Headless: `--screenshot x.png --play M01 --ticks N --results won|lost|won-stats|lost-stats [--age TICKS] [--sample-stats]` and `--screen results --age TICKS`.

There **is** a results screen. The exe goes `7 playing` -> `9` (lost) / `0xa` (won) -> `0x16` (statistics) -> `0x19` (campaign map, won) or `0x1c` (main menu, lost). The state number is `[0x5baa8c]`, set by the win/lose check (`0x4212f0`, docs/ai.md); the dispatcher `0x42d020` runs the handler of state `n` from the jump table `0x42d624[n-1]`.

## 1. The banner (states 9 and 0xa, `0x4357a0`)
- First frame: speech `sounds\speech\01-mis-failed.wav` (state 9) or `01-mis-complet.wav` (`0x407f30`, docs/audio.md). The game's frame surface `[0x5dde34]` is blitted to the screen and locked, and `0x45d400` processes it: **every even row is tinted dark red, every odd row is black**. RGB565 (`[0x517aec] == 2`): `p = (p & 0xf800) | ((((p >> 1) & 0x380) | (p & 0x1c)) >> 2)` (red kept, green and blue reduced to their top 3 bits placed in the low bits of their fields); the RGB555 branch is `((p >> 2) & 0xe7) | (p & 0x7c00)`. `endscreen::banner_rows` / `tint565`, emulation-checked (`opensow scanlines banner|banner555`, 900 random cases, odd heights included: the exe works on `H/2` row pairs).
- The picture is a `.tsp` loaded by `0x45dcd0` from `sprites2\extras\WinLoose` (built by `0x432440`: the language folder `diffdata\SK|CZ|PL|HU|RU|CHINNESSE\` prefixed by the language of `[player+0x6bf734]`, empty for English), file `Data\Sprites2\Extras\WinLoose.tsp` and a copy per language under `Data\DiffData\<LANG>\Sprites2\Extras\`. Frame 0 (410x121 "MISSION SUCCESSFULLY COMPLETED", `[0x5e71c0]`) is drawn when the state is not 9, frame 1 (223x79 "MISSION FAILED", `[0x5e71c4]`) when it is; `0x45edf0(W/2 + [0x71ceb8], H/2 + [0x71cebc], 0, frame)`: top-left = screen centre minus the hot spot (the offsets are 0). The text is baked into the picture, there is no lang string.
- A counter `[state+0xa8]` adds the ticks of each frame (`[0x552494]`, 60 Hz). From **120 ticks (2 s)** on, a mouse button (`[player+0xa]`, `+0x1a`) or **any of the 250 key flags** (`0x6bed6c + i`) leaves: `0x42c320(0x1c)` for a lost mission or `0x1d` for a won one (stored in `[0x5baa90]`, read by the statistics screen), then `0x42c260(0x16)` -- or state `0x1c` (main menu) when the mission number `[0x49a33c]` is 0, the tutorial.
- `[0x5baa8b]` (never written in the image) would instead go straight back to state 7 and `0x425d00`; unused.

## 2. The statistics screen (state 0x16, `0x434250` -> `0x44d890` init, `0x44d770` per frame, `0x44cbd0` draw)
Class object `0x70f814`. Init: music `statistic.wav` (`0x407bb0`, `Data\Sounds\Music\Statistic.wav`), pictures `data\pictures\statistic.srf` (640x480, the four pane pictures with frames) and `statistic2.srf` (1920x1080 backdrop, `[0x5ddefc]`, `[0x5ddf00]`), the 50-frame sprite file `sprites2\menu\statistic` (`.tsp`, `[0x71cde8..]`: frame 0 = a 22x1 blue bar row (hot 11,-1), frame 1 = the same in green).
- **Draw** (`0x44cbd0`): backdrop stretched over the whole screen, then the 640x480 picture at 1:1 centred (`W/2 - 320 .. W/2 + 320`, `H/2 - 240 .. H/2 + 240`); the eight labels (`0x44d500`, 12 px GDI font `[0x5ddf1c]`, colour (206,206,206), shadow (25,45,16)); the 16 bars.
- **Numbers** per side `s` (0 = player blue, 1 = enemy green) at `0x6bf788 + s * 0x80 + 4 + 4 * k` (reset by `0x465220`): k = 0 buildings **captured**, 1 buildings **lost**, 2 units **produced**, 3 units **lost**, 4 turrets **built**, 5 turrets **lost**, 6 air forces **sent**, 7 air forces **lost**. Where the exe counts them (and where the sim does, `World::stats`): captured/built = the object creation `0x43a420..0x43a068` (a captured building is rebuilt for its new owner, turrets of kinds 25-29 count as built), lost = building destruction `0x409ee8` (turret) / `0x409ef0`, produced = the factory exit `0x4087ed` / `0x408a11`, units lost = the dead-unit sweep `0x421fc1`, sent = aircraft launch `0x467eef`, air lost = an aircraft shot down `0x467b12`.
- **Layout** (relative to the screen centre): four pictures (2 x 2), each with a pair of bar pairs: picture 1 (top left) buildings captured / lost, 2 units produced / lost, 3 (bottom left) turrets built / lost, 4 air sent / lost. Bar centres per pair `-250/-225`, `-95/-70`, `+76/+101`, `+221/+246` (blue, green); base line `cy - 40` for the top pictures and `cy + 199` for the bottom ones; labels (string ids 1-based): `0x163` CAPTURED, `0x164` LOST, `0x165` PRODUCED, `0x164`, `0x166` BUILT, `0x164`, `0x167` SENT, `0x164`, top-left at x `-283, -104, +43, +216` / y `-27` (top row) and `-258, -104, +63, +216` / y `+212`. `endscreen::PAIR_X`, `ROW_BASE`, `LABEL_POS`, `PAIR_LABELS`.
- **One bar** (`0x44d370(x, base, side, value, picture max, flag)`): shown value `min(c, value)`; height `shown * 140 / picture max` pixels (0 when the maximum is 0), drawn as `height` rows of the 22x1 frame stacked upwards with the additive blit `0x45cde0` (twice while `flag` is set: a flash); then the number (decimal) centred on the bar x (`x - width/2 - 1`, 2 px left margin) with its top at `base - height - 20`, colour font `font_msg2` (font id 10 of the exe's table: 0 small_i, 1 small_o, 2 medium_i, 3 medium_o, 4 big_i, 5 big_o, 6 msg_i, 7 msg_o, 8 font02_dark, 9 font02_light, 10 font_msg2, 11 font_briefing_small, 12 font_briefing_big), spacing -2. Nothing is drawn while the counter is <= 0.
- **Animation** (`[state+4]` = ticks `t` since the screen opened; the update adds `[0x552494]` per frame): the shared counter is `c = 2t` when `S >= 600`, `t` for `S >= 400`, `t/2` for `S >= 200`, else `t/3`, where `S` is the sum of the four pictures' maxima (`endscreen::counter`, `speed_sum`). The pairs fill one after the other: pair 0 uses `c`, pair `k+1` uses `c_k - max_k - 2` (`pair_counters`), where `max_k` is the larger value of the two sides. The scale of a pair's bars is its picture's maximum (`pane_max`). The "complete" flag of a pair is `0 <= c_k - max_k < 2` (`pair_top`): it draws the bars twice (brighter) and plays sound **47** (`statistic-top`) once per pair (`[state+0x14..0x1b]`); sound **48** (`statistic-up`) plays for every bar that is still growing every 4th tick (`[state+0x10]` wraps at 4, `[state+0xc]` = 1). When the last pair completes `[state+0x28] = 1`.
- **Input** (`0x44d770`): Esc (`[player+0x65]`) or the left button: while `[state+0x28] == 0` it only completes the animation (`t = 1000000`, no sounds); the next one leaves. Network game: state `0x1c`. Otherwise by `[0x5baa90]`: `0x1d` (won) -> `0x42c260(0x19)` = the campaign map and `Pass(mission)` (`0x4565a0`, docs/lands.md); `0x11` -> state `0x11`; anything else (lost) -> **state `0x1c`, the main menu**.
- The screen frees its pictures when the state leaves `0x16` (`0x44d827`).

## In OpenSOW
`Game::update` raises `Results` when `World::outcome` is set (speech as before), `draw_banner` paints over the frame of the frozen mission, a click/key after two seconds opens the statistics (`statistic` music; the tutorial goes straight to the main menu), and leaving them calls `results_event(Done)`: won -> `progress.pass` (`pass_warmonger` for Warmonger) and the campaign map, a won skirmish, a lost mission and the tutorial -> main menu. The final mission still plays `mO` before the closing message. The progress is passed when the statistics are left (as in the exe). The banner tint (`endscreen::banner_rows` / `tint565`; `record::op::TINT_ROWS` on the GPU path), the bar arithmetic (`endscreen`), the sounds 47 / 48 and the input rules are the exe's.

**Differs from the exe:** the English statistics labels use the small bitmap font instead of the exe's 12 px GDI Times New Roman (`Results::draw_layout`); the other languages use the 12 px system font (`gdi.rs`) with the same colours and shadow, because the bitmap font has no accented letters (Slovak "STRATENÉ" lost its É).

**Differs from the exe:** the banner picture is scaled like the HUD (window height / 768, never below 1, `Results::draw_banner`); the exe blits it 1:1.

**Differs from the exe:** the statistics page (the 640x480 picture with bars, labels and numbers) is drawn at 640x480 and scaled to the largest centred 4:3 rectangle over the stretched backdrop (`Results::draw_statistics`); the exe draws it 1:1 at the screen centre.

After the final mission's `mO` the port shows its own "Campaign complete!" message, and a won skirmish returns to the main menu (both not in the exe).

## Open
- Result code `0x11` of `[0x5baa90]` (state `0x11` after the statistics) and who writes it were not traced.
- Whether the "produced" counter also includes level-loaded units: `0x43a420` increments it only for an explicit handle (savegame / network), so only factory output counts here.
- Air "lost" counts shot-down aircraft only; the unload path at `0x467b12` was not followed to the end.
- The music track loops in OpenSOW; the exe's stream behaviour was not checked.
