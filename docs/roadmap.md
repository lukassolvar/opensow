# Roadmap

1. [done] Asset parsers: archive, SRF, sprites, shadows, map, tile index, fonts, videos, savegame container.
2. [done] `.edt`/`.net` structure, air stock, weapon points, `generic.file`, lang files and every level header / object word the engine reads (docs/ai.md, docs/levels.md); the other header words are ignored by the exe.
3. [done] Map viewer: background, overlays, buildings, turrets, units, bullets and effects (aircraft are drawn in the game); the `.til` foreground, the minimap (`N`) and the `.srfa` question are done (`.srfa` is the unused low-detail background, docs/formats.md).
4. [done] Audio (WAV, speech, music) and the `.sgv` videos (MPEG-1, MP2, Indeo5, CRAM; intro, briefings, outro and the campaign map play in the game).
5. [done, apart from the items under "Still open"] Exe analysis by disassembly and emulation (`scripts/verify_against_exe.py`, `scripts/verify_net.py`): game loop, unit/AI/combat logic, air forces, level loader, network frame messages.
6. [in progress] Deterministic simulation port: the decoded rules are in `opensow-formats` and `sim.rs`. Decision (2026-11-06): no whole-game validation against the original (no Wine/CrossOver runs, no original savegames as ground truth); correctness rests on function-level exe emulation (`scripts/verify_against_exe.py`) plus our own golden-trace regression tests (see "Gaps and ideas").
7. [protocol decoded, not played] Networking compatible with the original protocol: it is a client-command / host-snapshot design (docs/network.md), decoded and exe-checked as `formats::netsync`; no network play in the game (optional).

- [done, prototype] `opensow-game`: menus (original button art), mission select and campaign map, selection/move/combat/win-lose, production, tech-levels, economy, turrets, Advancer actions, air strikes, computer opponent, audio, tutorial, save/load (the exe's savegame stream plus our extension, docs/savegame.md), skirmish vs the computer with difficulty levels (docs/skirmish.md), custom maps and the in-game map editor (docs/map-editor-ingame.md), with new layouts composed from the missions' own art (docs/generated-maps.md, docs/map-design.md); the launcher (docs/launcher.md) starts it. Placeholders are listed in docs/game.md.

## Gaps and ideas (review 2026-11-06)
Not decided to be done; ordered roughly by value.
1. **Golden-trace regression tests**: with no original to compare against, pin our own sim. Per mission (a few), run N ticks headless (`--play Mxx --ticks N --report`) and check in a compact trace (unit/building HP and positions, credits, RNG state) that `cargo test` compares. Catches accidental changes to tick order or RNG call order. Tests that need the install skip without it.
2. **Warmonger coverage**: audited and integrated as a campaign toggle on the world map (docs/warmonger.md); remaining: trace the few differing mission-number rules of its exe and check its in-game strings.
3. [done] **Text and languages**: non-English text is drawn with `gdi.rs` (Times New Roman / Arial Bold, CJK fallback face); only EN/SK/CZ/CS/CT are offered, PL/HU/RU fall back to English (docs/text.md).
4. [done] **CHuffcomp**: it is the savegame compressor, the only use found (`save::huff_encode`, docs/savegame.md).
5. [done] **Destruction animation**: a dying building shows its destroyed frame (state 5), a dying turret its wrecked base without the gun (docs/art.md).
6. **Pathing grid**: one merged grid rebuilt each tick instead of the exe's incremental updates (docs/walking.md); small known deviation.
7. **Distribution and platforms**: signed / notarised builds (docs/release.md). Done: the application icon on every system, the release files (universal macOS `.dmg` with `OpenSOW.app`, Windows `.zip`, Linux `.tar.gz`) built without the dev features, and CI on Linux, macOS and Windows (`.github/workflows`, docs/release.md), locating the install without Steam (launcher: Locate, drop, Auto-detect), GPU presentation (`gpu.rs` / `replay.rs`).
8. **Playability polish**: gamepad or touch. Done: resolutions up to 3840x2160 and Native (docs/options.md), skirmish difficulty Easy..Brutal (docs/skirmish.md).
9. [done] **CI**: fmt, clippy and the tests on Linux, macOS and Windows plus the release files on every push (docs/release.md); tests that need the install skip there.
10. **Extras**: mod support. Done: map editors (internal: docs/map-editor.md; in-game for custom skirmish maps: docs/map-editor-ingame.md), PNG export/import for local art experiments (docs/art-import.md).
11. **Docs hygiene**: fold the dated "Decoded since" log into the groups, and fix `docs/game.md`, which says "no unit collision" while describing the exe's local avoidance.

Out of scope by decision: running the original under Wine for tick-by-tick comparison, and using original savegames as ground truth for the sim (savegame work itself is in scope again: its aim is the original's exact format, checked by exe emulation, see "Still open"). Multiplayer: the lockstep RNG (`rng.rs`) can only be checked by emulation, not by a live session.

Decoded since (2026-11-06, savegames): writers for every record and the whole stream, store-branch emulation checks (`scripts/verify_save_store.py`, `scripts/verify_save_state.py`, shared `scripts/savestore_lib.py`), `opensow saverec|savestate`, corrections to the record tables (docs/savegame.md "Corrections found by the emulation"), 76 more field names (128 -> 204 of 271).

## Still open
The groups below are what is left; "done" groups are kept as a short record of what the exe analysis settled.
- **Savegames** (docs/savegame.md, docs/saveload.md): the container, the whole state stream, every object record and the map object are decoded, **readable and writable** (`Object::write`, `State::to_bytes`, `MapState::to_bytes`, `huff_encode` byte-identical to the exe's compressor) and **verified against the exe's own store branch in an emulator**: `scripts/verify_save_store.py` (14 record classes, 840 random objects, every parsed field equals the emulated memory at its offset) and `scripts/verify_save_state.py` (the whole `0x42a400` on 40 randomised game states, byte-identical re-write). That check corrected the old notes (bullet sparks are triples; the campaign record has a 4-byte header; decal-flag grid orientation). All 271 serialised scalars are named. **Bridge (first slice done)**: `World::to_state` / `apply_state` (`sim/savestate.rs`) write and read the exe's stream for head, economy, map layers, buildings, units, turret guns, bullets, aircraft squads, decals; a save file is now the exe-layout stream plus an `OpenSOW3` extension after the `Checksum` tag (exact continuation for us, valid layout for the exe), a file without the extension loads through `apply_state`; handles decoded (`0x43a9b0`, the four byte arrays are generation counters). Test `a_mission_round_trips_through_the_original_state_stream` (5 missions, byte-identical second stream). **Bullets, aircraft squads, clouds, the order list, the Advancer's action and beam timer, the AI strategy / timer, the mission countdown and the real campaign progress are in the stream too.** the Advancer beam bullets, corpses, blinks and turret look timers too. the Rogon blast and the tops' weapon state too (the exe's load code accepts all of it, `scripts/verify_save_load.py`). **Units are complete too**: top, chassis, embedded weapons and the Advancer's beam weapon start from the exe's own unit initialiser (`scripts/gen_unit_defaults.py`, `sim/unit_defaults.rs`), the sprite size words come from the install's sheets (`SheetSizes`), and the unit's pixel line is the chassis' local route (the sim keeps the exe's point list). The tutorial script and the visual RNG are not in the original's stream by its own design (docs/savegame.md), so only our extension carries them. **Open**: the purpose of the input record's ten `CArray`s (written, never used by the game); streams are verified against the exe's load branch for 5 missions and 5 synthetic worlds (`scripts/verify_save_load.py`).
- **Multiplayer**: the wire protocol is decoded and exe-checked (docs/network.md): header, input packages, the ten command queues a client sends, the host's per-frame state snapshot (building, unit, aircraft, bullet records), `formats::netsync`, `opensow netmsg|netsync`. Open: applying a received snapshot to a running game (the readers create live objects) and DirectPlay session handling; the game itself has no network play.
- **Air strikes** (docs/air.md): all decoded and ported (launch, click handler, pointer 10, tick scheduling, death sequence, AI pick, mission-script carryalls). Recharge is the air base production (docs/production.md).
- **Combat/effects** (docs/projectiles.md, docs/effects.md): done. Unit corpses (`unit+0x90/94/98`), top aim offset `[top+0x60]`, bullet sprites and variants are decoded; bullet type 23 has no local creator. Bullet network serialisation (`0x4128f0`) is done too (`netsync::BulletSync`).
- **AI/walking** (docs/ai.md, docs/walking.md, docs/art.md): done, the turret routine included (the old simplified tier rule is gone). Placement test (with the map's no-build layer), unit slots instead of the 60-unit placeholder, the walk-animation "moved" rule, order words and the mission survey are decoded. Left as a small deviation: one merged grid rebuilt each tick, updated when a unit changes cell (docs/walking.md).
- **Levels**: done. The exe reads only the header words listed in docs/ai.md (all others are ignored); the object words are decoded (docs/levels.md: w13 is unused, hit points come from the percentage w18, neutral buildings start at half). Found on the way: the campaign's air-force stock belongs to the player (word 5+3g), not the enemy.
- **UI/text**: done. First-run defaults were already in docs/options.md; F2 abandons the mission to the campaign map (implemented); the HUD message push is row 30 of the step table (30 px/s); the save-title limit is measured with `font02_light` at spacing -4 like the exe; bitmap spacings are per call site (docs/fonts.md).
