# Playable prototype (`opensow-game`)

Run: `cargo run --release -p opensow-game` (needs the game install, see README). Code: `crates/opensow-game/src`:
`main.rs` (the `Game` and `App` types, CLI; methods in `game_flow.rs`, `game_screens.rs`, `game_input.rs`, `window.rs`, headless runs in `headless.rs`), `menu.rs` (screens, layout, actions), `play.rs` (camera, selection, drawing), `sim.rs` + `sim/*.rs` (pure simulation, split by subject: see the table at the top of `sim.rs`, unit-tested), `ui.rs` (software drawing, bitmap-font text), `assets.rs`.
Rendering reuses the viewer library (`opensow_viewer::{art, render, scene}`).

## Screens
- **Main menu**: backdrop `Data\PICTURES\MainMenu.srf` (the Steam 1920x1080 art), buttons from `Data\Sprites2\Menu\001_buttons.tsp` (frames 0-5 highlighted, 6-11 normal: NEW GAME, LOAD GAME, TUTORIAL, MULTIPLAYER, OPTIONS, EXIT GAME). The frames' `extra` field `[640, 480, 320, 240]` is the design resolution and its centre: `hot` is the offset from the screen centre; the Steam backdrop has the logo on the left. Code: `menu.rs` (`MAIN` rows).

  **Differs from the exe:** the button column is placed under the Steam backdrop's logo (x 20.6%, y 58% of the window, rows 52 px apart at 1080p) instead of at the frames' design offsets from the screen centre, and there are eight rows: SKIRMISH and MAP EDITOR (not in the exe) are drawn as text between MULTIPLAYER and OPTIONS.

  **Differs from the exe:** the highlighted frames carry the original 640x480 backdrop behind their glow (the exe copies them plain, `0x445620` -> `0x45edf0`), which shows as a grey rectangle on the Steam art, so `ui::sprite_glow` keeps only their green part.

- New game = the campaign map with 22 lands and the `mA` animation (docs/lands.md; progress written to `player.cfg` in the save folder, `Game::save_progress`); `L` on the main menu lists every mission.  Options = the original screen (`options.rs`, docs/options.md: art, switches, volumes, scroll speeds, resolution, sounds, plus the port's page 2; the audio rows act live, the rest applies on O.K., which writes `State of War_1.cfg` and `opensow.cfg`); the prototype's own settings (game speed, health bars, weapon ranges, starter squad) moved to key `P` on the main / pause menu (not in the exe). Pause (Esc) = the original in-game oval menu (`ingame.rs`, docs/pause.md: continue, load/save (`saveui.rs`, docs/saveload.md), options, restart / main menu with check / X confirmation, sounds 35-39), mission end: the original banner and statistics screen (`results.rs`, docs/results.md); P pause is the original dimmed frame (docs/pause.md).
- Boot screens (`boot.rs`, the exe's `CMenuCopyright`, screen 23): `CS.srf` (Cypronia logo, 2 s), `presents.srf` (2 s), then `nazov.srf` (title art, 3.3 s), centred on black, no fade; a key skips a page once its timer is >= 60 ticks (the title page starts at -80); every page start restarts `Music\uvod.wav` (the exe plays it from the constructor and from each page's branch, `0x4421dd..0x4426f8`; no SFX on page changes). The menu follows them (the intro plays later, before the campaign map: docs/video.md); `--no-intro` skips them, `--boot-page N --screenshot` renders one. 

  **Differs from the exe:** a left click skips a page at once, whatever its timer (`Boot::skip_now`).

  **Differs from the exe:** the Steam exe's own transitions skip its `presents.srf` branch (state 6); we show it anyway to match the original's three screens.

  `CI.srf` (PC Mania logo) is referenced by neither exe, so it is not shown. Warmonger has no `presents.srf` and shows two pages.
- Load game opens the load page (`saveui.rs`, docs/saveload.md: ten slots, screenshots, typed titles; files in `$OPENSOW_SAVE_DIR` or the user's data folder; a save continues the mission, in the original's state-stream layout plus our extension, docs/savegame.md). Tutorial starts M00 directly (no movie; its end returns to the main menu, docs/tutorial.md); Multiplayer opens the original lobby screens (docs/multiplayer-menus.md).

  **Differs from the exe:** the lobby runs offline (the DirectPlay transport is stubbed, `multiplayer.rs`) and ACCEPT only shows a notice; there is no network match yet.

  Skirmish (port's own row, not in the exe, docs/skirmish.md) opens the port's own full-window setup screen (`skirmish_ui.rs`) for a match against the computer on any multiplayer map, with a map preview and both sides' resources editable. Map editor (port's own row, not in the exe) opens the players' map editor (`mapeditor_ui.rs`, docs/map-editor-ingame.md).

## Simulation (`sim.rs`) - what is real and what is a placeholder
Real (decoded, see the other docs): chassis walk/turn animation (`anim`), weapon top aiming and fire sequences (`aim`, `recoil`), target search over the range rings with the exe's priority unit > turret > building (`rings`), bullet paths and speeds (`projectile`), area damage radius 32 px incl. friendly fire, unit max HP (`UnitKind::max_hp`), object HP from the level script, anti-air weapons ignore ground targets.
Effects (bullets, blasts, building/unit/air explosions) are drawn with the real sprites (docs/effects.md); `--fx CX,CY,KIND,AGE` (KIND blast0..6, turret, building, air, cloud, wreck, puff, smoke, decal, satlaser, piece, missile) places one for a headless screenshot; `--destroy CX,CY` destroys the building or turret covering that cell (the destruction burst, docs/projectiles.md).
Paths come from the exe's wave search (docs/pathfinding.md); ground units avoid each other and building corners with the exe's local search (docs/walking.md) and wait when blocked.
Decoded since: the computer opponent (docs/ai.md), economy and tech-levels, turret placement and the five turret guns, air strikes and anti-air, Rogon bombs, satellite protection, Advancer actions (docs/advancer-actions.md), win/lose rules, mission countdowns and reinforcements, convoy missions 3 and 8, HQ Advancer replacement, building footprints, the exe's random table.
Mouse (docs/controls.md): the left button selects and commands according to the pointer (go-to, attack, Advancer capture/upgrade/repair), left drag box-selects, right click deselects/cancels, right drag scrolls. Rally point: select an own factory and press `R` or click the RALLY POINT button above its top slot icon, then click the map (docs/rally.md). Keys (deviations: docs/hotkeys.md): `R` (no factory selected) or right click on an own building with the Advancer: repair/upgrade mode; the pointer is the original's `cursor.ps6` (docs/cursor.md), `1`-`5` then click: turret, `T`: tech-levels, `B M C Y F` then click: air strike (bomber, meteor storm, carryall, tripler, fighter), `Q` select all regular units (Advancers and nuclear vehicles are only ever selected alone, by clicking them), `P` pause; the full key list of the original and what is ported: docs/hotkeys.md (Tab, Backspace, H, numpad `* / -`, numpad bookmarks, F3/F4 speed).
Placeholders / not implemented (marked `PLACEHOLDER` in code):
- starter squad (not in the exe; optional, off by default since the original has none: 8 units next to the Advancer when a mission starts with fewer than 4; mission 1 and 4 get their units from the start carryalls);
- no fog (the original has none);
- the tutorial's instruction panel is the original's (wrap, dark box, coin, sliding arrow; docs/tutorial.md);
- **Differs from the exe:** no network play (the multiplayer lobby runs offline, docs/network.md);
- sound is complete as far as the exe plays any: menu, map, weapon, impact, beam, aircraft and explosion effects with the exe's pan and distance rules, speech (incl. `01-game-saved`), music and the tutorial voices (docs/audio.md). The exe has no unit idle sounds or voices (all 82 effect call sites were scanned), so there is nothing to port;
- air-strike icons recharge only through the air base's production slots (as in the exe, docs/production.md); a destroyed building stays on the map, dead, while its destruction animation runs (about 3 s for buildings, 0.75 s for turrets, `Structure::dying`, docs/projectiles.md), drawn in its destroyed frame (a turret as its wrecked base without the gun; docs/art.md), with no health bar and its selection cleared.
Victory/defeat: docs/ai.md ("Win, lose and mission scripts").

## Camera zoom (not in the exe)
The mouse wheel zooms the mission map (the original has one fixed scale): 8 % a notch, a trackpad's small deltas by their share, eased in over a few frames (`Play::wheel` aims, `Play::ease_zoom` moves a share of the way each frame, about 90 % in a fifth of a second) with the map point under the pointer kept in place; from filling the window with the map (at least 0.3) to 3x. The map editor's camera works the same way (docs/map-editor-ingame.md).

**Differs from the exe:** the original has one fixed scale; with "Map zoom" on (the default) the view can be zoomed, and above zoom 1 the world is drawn from enhanced copies (docs/enhance.md).

 Options page 2 "Map zoom" (on by default) switches the mission zoom off: the original scale 1 and no wheel (docs/options.md).

## HUD (`hud.rs`)
Laid out from the exe's widget positions, see docs/hud.md (counters top left, radar top-right corner, air pills down the left edge, turret tabs bottom right, tabs only for tiers the level allows, pills only for forces in stock, tiles only once there are credits / research). The info box (docs/hud.md: slides in at the top right for a selected own building or a hovered icon, blue static, typed stats next to the animated picture, then the description; sounds 51 / 52) and the production slot icons with their buy arrows and bars are decoded (`0x437390`). Our additions that are not in the exe: the price over a hovered turret tab, and the armed air pill keeps its hover glow.

**Differs from the exe:** the HUD scales with window height / 768 (never below 1); the exe draws it unscaled (docs/hud.md).

## Testing without a window
`--screenshot out.png [--size WxH]` renders any screen (`--screen main|levels|prototype|options|pause|results|message|lands|multiplayer|skirmish|mapeditor`, `--hover N`) or a mission (`--play M01 --select-all --move CX,CY --ticks N --center CX,CY --zoom Z --range --report`). `cargo test -p opensow-game` runs the simulation tests and scripted UI flows (menu navigation, box select, move order, pause) against the install; they skip without one.

- Mission pointer: the pointer is the system's cursor, built from the same `cursor.ps6` frame, hotspot and HUD scale the software pointer uses (`Play::pointer_cursor`, `App::update_cursor`), so the compositor moves it at the mouse's own rate instead of once per rendered frame; `OPENSOW_SOFT_POINTER=1` draws it into the frame like the original's non-HW-cursor mode (docs/options.md). Headless screenshots always use the software pointer. On macOS the cursor image is sized in points (the image is made at scale / display scale).

  **Differs from the exe:** the exe draws the pointer into its frame or, with HW CURSOR, from its mouse thread (docs/options.md); here it is the system cursor.

- GPU drawing: the frame is no longer drawn on the CPU when a GPU is there. While `record::begin` .. `end` runs (`opensow_viewer::record`), every drawing primitive (`render::rect/blit*/stamp*/foreground`, `ui::*`, `gdi`, and the menus' page and backdrop copies) appends a 16-word command instead of writing pixels: the clipped screen rectangle, the blend, and per screen column and row the source column and row, computed with the software loop's own formula. `replay.rs` uploads the commands with per-16x16-tile lists; one compute thread per pixel walks its tile's commands in order with the same integer arithmetic (the exe's RGB565 blends, the screen mask as bit 24), so the picture is bit-identical to the CPU's. Sprite frames and static pictures are copied once into a GPU atlas, the map into a ground buffer; menu pages, movie frames and text coverage go up per frame. The lens blend reads the picture as it was before it, so the replay runs in segments split at lens commands. Menu pages (options, save, multiplayer, campaign map, statistics) are still drawn on the CPU at 640x480 inside `record::cpu` and handed over as one picture. Frames that take a save thumbnail from the picture stay on the CPU. `--screenshot ... --gpu-check` draws the frame on the CPU, records it, replays it on the CPU and on the GPU, and prints the differing pixels (0 everywhere: missions with clouds, combat, zoom, every menu screen, boot pages, movies, 640x480 to 5120x2880), plus a synthetic frame that uses every operation. At 5120x2880 missions went from 39 to 60 fps (about 1 ms of CPU per frame for the recording), the main menu from 52 to 60. The anti-aliased GDI stand-in text now mixes with an 8-bit alpha (integer, same on both sides). `OPENSOW_CPU_DRAW=1` draws on the CPU and only presents on the GPU.
- Frame time: the window is software-rendered, so the cost grows with the pixel count (2560x1600 took 19.5 ms to draw + 7.7 ms to present at first, 37 fps). The per-pixel passes (background, foreground mask, the big blends such as the clouds) now map columns once per call, use inlined pixel helpers and run in bands of rows on several threads (`render::par_bands`), output pixel-identical (checked A/B at 640x480 and 1280x800 with clouds): about 9 ms + 8 ms, 58 fps. Resolution and presentation: the game draws at the Options resolution (640x480 .. 1920x1080 like the exe, plus 2560x1440 and 3840x2160) into its own buffer, whatever the window's size; the game starts fullscreen (borderless on the current screen, F11 toggles, `--windowed` opens a window of that size instead); while fullscreen and focused the pointer is held inside the window, so it cannot move onto a second display (the exe's exclusive DirectDraw mode keeps it on its one screen): `App::confine_cursor` asks the system to confine it (Windows, X11, Wayland); macOS has no confinement, so there a pointer that leaves the window is moved back to where it left (`CursorLeft`, or a drag past the edge); losing the focus or going windowed frees it; NATIVE (the first-run setting) draws at the window's own pixel size, so nothing is scaled: a 5K screen (5120x2880) runs a mission at about 40 fps, 19 ms draw + 5.5 ms present and the frame is scaled into it (aspect kept, black bars), mouse points mapped back (`fit_rect`, `App::to_game`). The GPU scales with sharp bilinear (not in the exe, which drew at the screen mode's own size): each game pixel stays a solid block and only the window pixel where two blocks meet is blended, so at whole-number scales (NATIVE, 2x, 3x) the picture equals nearest neighbour. Plain nearest neighbour at a non-integer scale (1024x768 in a 1920x1080 window is 1.40625) showed every second or third row and column twice, and those fixed doubled lines read as a grid while the map zoomed and scrolled under them (a Windows report); tests `gpu::tests::*` draw offscreen and check both (skipped without a hardware GPU: CI has none on Linux and only the WARP software adapter on Windows, which crashed the test process). The softbuffer fallback still scales nearest neighbour (`blit_scaled`). The GPU (`gpu.rs`, wgpu: Metal on macOS) uploads the frame as a texture, scales it and presents with vsync; at 3840x2160 in a Retina window the menu went from 28 fps (CPU upscale + softbuffer present, 24 ms) to a steady 60. `OPENSOW_SOFTWARE=1`, or no usable adapter, keeps the softbuffer path. Without the GPU replay (above) sprites and the map are drawn on the CPU (about 8.5 ms for the 4K menu, 14 ms for a 4K mission frame). `OPENSOW_PERF=1` prints frames per second and the milliseconds per stage once a second, `OPENSOW_START=M01` starts a mission directly (for profiling in the real window; `sample <pid>` shows the hot spots).

  **Differs from the exe:** 2560x1440, 3840x2160 and NATIVE are not in the exe's resolution table, the exe's first run is 1024x768 (docs/options.md), and it has no scaling of a smaller frame into a larger window.

- **Chat line and cheat codes** (original feature, docs/chat.md): Enter opens the line, Enter sends, Esc cancels, Tab recalls the last line; nine cheat phrases (`give me money`, `give me fighter`, ...) are the exe's own. Headless: `--chat TEXT [--chat-send]`.

## Dev tools (`devtools.rs`, not in the exe)
`F12` or the backquote key shows / hides an overlay panel in the game's own look (dark green plate, small font, green frames); drag its title bar to move it. While hidden, a small badge at the bottom left lists the tools that are still on (click it to open the panel). Tools:
- **Unlock all missions**: every locked land of the campaign map opens (the saved progress is not touched; `Game::effective_progress`). `L` on the main menu still lists all missions.
- **Game speed** 1x / 2x / 5x / 10x: multiplies the tick rate (`Play::update` allows more steps per frame to keep up).
- **Invulnerable units** (own units keep full HP), **infinite credits + research** (kept at the caps), **freeze enemy** (the computer player, enemy units, turrets and factories do nothing): `sim::Cheats` in `World::cheats`, applied each frame, never saved.
- **Place unit**: pick MINE / ENEMY and a unit kind, then click the map (nearest free cell; the target cell is tinted, red when blocked); right click or Esc stops.
- **Place turret / building**: TUR 1-5, HQ, light / medium / heavy factory (LFAC, MFAC, HFAC), AIR base, GOLD mine, LAB, WIND trap, walker factory (WFAC) for MINE / ENEMY: the clicked cell becomes the footprint's top-left cell, any terrain, full hit points, no cost or range rule; refused only off the map or on another living structure (`World::dev_place_structure`). Buildings get no production slots (the level scripts supply them), an HQ links a free Advancer of its side.
- **Add air force**: BOMBER / ASTEROID / CARRYALL / TRIPLER / FIGHTER buttons add one to the air-force stock of the chosen side (MINE / ENEMY); launch it with the usual HUD icons.
Headless: `--screenshot x.png --play M01 --dev show,air,god,rich,freeze,unlock,x5,enemy,arm=KIND,place=KIND:CX:CY` (omit `show` to see the badge).

## Measuring drawing speed

`--screenshot out.png --gpu-check` also prints timings. The line `steady state: cpu draw X ms, record Y ms` is what a running
game pays per frame once the caches are warm (the fastest of eight draws): `record` for the normal path, where the frame is
recorded and replayed on the GPU, and `cpu draw` for the fallback that draws every pixel on the CPU. Measured 2026-11 on an
Apple M5 Pro at 1920x1080: a busy skirmish records in about 0.2 ms and replays on the GPU in under 4 ms (including the
readback the check needs); the CPU fallback takes 6-7 ms at zoom 2 with all effects. The slowest screen is the main menu,
about 11 ms. A frame at 60 per second has 16.7 ms.
