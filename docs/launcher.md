# Launcher

The launcher is not in the exe; the original starts straight from `State of War.exe`.

`cargo run --release -p opensow-launcher` (code: `crates/opensow-launcher`: `ui.rs` layout and drawing, `text.rs` texts, `settings.rs` the game's settings files; launcher settings: `formats::launcher`).

## Pages
A sidebar on the left lists **Home**, **State of War**, **State of War: Warmonger** (on two lines) and, at the bottom, a **GitHub** link (opens `https://github.com/lukassolvar/opensow`, or `OPENSOW_UPDATE_REPO`'s repository; `update::repo_url`) above **Settings** (gear). Its header shows the icon, "OpenSOW" and this launcher's version (`v0.2.0`), on every page; while a newer release waits it reads `v0.2.0 → 0.3.0` and the header opens Settings → Launcher (see Updates). Each game entry shows its state as a badge and a line: green tick "Ready to play", red cross "Game files missing" (a folder is set but the game is no longer in it), empty ring "Not located" (Warmonger adds "optional"; a Warmonger that is found while the base game is not reads "Game files found" in amber).

- **Home**: the general picture, the OpenSOW title (the icon only in the sidebar), a "Your games" card with both games and their state (a row opens that game's page), under it the **What's new** card (below), and a big **Play** that stays grey ("Locate State of War to play") until the base game is found. It starts the game on the campaign used last (both campaigns are one game, switched on its world map, docs/warmonger.md). While a game is not found, "Find games automatically" sits at the top right.
- **State of War** / **Warmonger**: the game's picture (cold blue / red grade), its title (no subtitle), a status line (found, files missing, or how to locate it) with the folder or what the folder must hold, Auto-detect and Locate game / Change folder at the top right. There is no Play here (only on the home page): while the game is not found, a big **Locate game…** sits bottom right, and once it is found that corner stays empty. Warmonger also needs the base game (it uses its art and sound); its page says so while the base game is missing. Warmonger is optional: nothing else depends on it.
- **Settings**, three tabs:
  - *Launcher*: the language (each with its flag drawn in code; English = UK, Chinese = PRC, traditional = Taiwan): English, Slovak, Czech, Chinese (simplified / traditional) or "From game files" (the install's `Data\lang.dat`, the original's own mechanism), and where the game settings are stored. `GameDir::language()` is what every menu asks; the movie folder index (`--lang`) follows it. Polish, Hungarian and Russian are not offered (English or damaged text, no art; docs/text.md); a saved one reads as "From game files".
    **Differs from the exe:** the exe only reads `Data\lang.dat`. With a language chosen here, the game ignores `lang.dat` (docs/text.md).
  - *Game*: everything of the original's Options menu (docs/options.md): resolution (the game's arrows: 640x480 .. 3840x2160 and Native), clouds 0-4, radar, screen shake, vertical sync, hardware cursor, keyboard and mouse scroll 0-10, and music / speech / effects each with its switch and volume (steps of 5), plus "Reset game settings" (the game's first-run values).
  - *Enhancements*: this port's nine switches (Options page 2 in the game) with their one-line explanations, in two columns.

Folders are set by Locate game (system folder dialog: osascript / zenity / PowerShell; on Windows PowerShell runs without a console window, the dialog is kept on top and the chosen path comes back as UTF-8 so folders like `C:\Users\Matúš\...` survive), by dropping a folder on the window (on a game's page it goes to that game; a Warmonger install always lands in its own slot), or Auto-detect (env var, then Steam's default places via `default_steam_dirs`, then the sibling Warmonger folder). Steam places searched, in order (not in the exe: the original simply runs from its install): the macOS console download (`~/Library/Application Support/Steam/Steam.AppBundle/.../steamapps/content/app_748040/depot_748041`); then for each Steam folder (`~/Library/Application Support/Steam`, `~/.local/share/Steam`, `~/.steam/steam`, Flatpak `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`, `%ProgramFiles(x86)%\Steam`, `%ProgramFiles%\Steam`) its console download `steamapps/content/app_748040/depot_748041`, then every library in `steamapps/libraryfolders.vdf` (the Steam folder first): `steamapps/common/<installdir>` from `appmanifest_748040.acf`, else any `common` folder named "State of War" (Windows, Proton). A folder counts when it or its `State of War` subfolder has `Data` and is not a Warmonger install. A Steam folder outside these defaults (registry `SteamPath`) is not looked up. **The folders are checked again** when the window gets the focus, on every page change and right before a start: files deleted between launches show as "Game files missing" and the home page's Play then opens State of War's page with a note instead of starting.

## What's new
The home page's card under "Your games" lists this version's changes at a glance: one line per bullet of its release notes, the bullet's bold lead (`- **Controls menu.** ...` gives "Controls menu"; a bullet without one gives its first sentence), tagged NEW (blue) for the sections `## New` / `## What's in it` / `## Added` / `## Changed` / `## Improved` and FIX (green) for `## Fixed`; other sections (Download, Known limitations, GitHub's "What's Changed") are left out (`update::parse_notes`). As many lines as fit are shown (four), then "+N more" and **All release notes ›** (the repository's releases page). The notes are `docs/releases/vX.Y.Z.md` of the launcher's own version and its translations `vX.Y.Z.sk.md`, `.cs.md`, `.zh-Hans.md`, `.zh-Hant.md` (`update::NOTE_LANGS`), all built in by `build.rs` (`update::OWN_NOTES`), so they show offline; the card takes the page's language and falls back to English where a translation is missing, and without the English file it is left out. Translated files use the same form with translated headings (`## Novinky` / `## Opravy`, `## 新功能` / `## 修复`, `## 修復`; `update::parse_notes` knows them). Only the bullets under New / Fixed are read; the rest of a translated file (the intro) is for readers of the file.

While a newer release waits, the card shows that release's notes instead (English: the `body` of the same GitHub answer the update check reads; other languages: the release's files `vX.Y.Z.<lang>.md`, which `release.yml` attaches from `docs/releases`, downloaded right after a newer release is found, `update::fetch_translations`, one small request per language; a failed one stays English) under "Update X available" with a pulsing dot, an **Install X** button and **Release notes ›** (its page); while downloading it shows the progress, once installed "Restart launcher".

**The badge:** while a newer release is found or downloading, an amber dot with an up arrow sits on the sidebar icon's corner; a ring grows out of it and fades every 2.4 s and the dot gives a small hop after it (`PULSE`, `App::hop`). It keeps pulsing as long as the update waits. Only then does the window keep redrawing, about 30 times a second (one frame about 3 ms at 2000x1240 on an M-series Mac; see Motion).

## Updates
Settings → Launcher → *Updates* shows this launcher's version (`CARGO_PKG_VERSION` of `opensow-launcher`), a **Check for updates** button and the switch **Check when the launcher starts** (on by default; `check_updates=0` in `launcher.cfg`). Code: `update.rs`. The check asks GitHub's public API for `/repos/lukassolvar/opensow/releases/latest` (`update::REPO`; `OPENSOW_UPDATE_REPO=owner/name` points elsewhere); a newer version shows "Version X is available: <title>", **Download and install X** and **Release notes** (opens the release page), the sidebar's Settings entry says "Update X", the sidebar header shows the pulsing badge and the home page's card the new release's notes (What's new, above). While a private repository or one without releases answers 404, the page says "No release has been published yet". The check at start is quiet: its result only shows on that page and in the sidebar.

**What a release must look like** (built by `.github/workflows/release.yml`, docs/release.md):
- tag `vX.Y.Z` (higher than the crates' version; drafts and pre-releases are ignored, and `-beta` style tags are not read);
- per system one file whose name contains the platform `<os>-<arch>` as Rust names them (`windows-x86_64`, `linux-x86_64`, `linux-aarch64`; `update::platform()`), `.zip` or `.tar.gz`, holding `opensow-launcher` and `opensow-game` (`.exe` on Windows) at any depth, e.g. `opensow-0.2.0-linux-x86_64.tar.gz`. Macs take their own platform's file when there is one, otherwise `macos-universal`; a `.dmg` is accepted on macOS only (`opensow-0.2.0-macos-universal.dmg` with `OpenSOW.app` at its top);
- next to each file `<file>.sha256` with its SHA-256 in hex (`shasum -a 256` / `sha256sum` output). Without it the launcher does not install; a mismatch installs nothing.

Install: the `.sha256` and the archive are downloaded with the system's `curl` into `<data folder>/update/` (a progress bar from the growing file), the hash is checked (`update::sha256`, own code), the archive unpacked with `tar` (`unzip` for zips on Linux; a `.dmg` is mounted read-only with `hdiutil` and unmounted after), and each program found (symbolic links are not followed: the image's `Applications` link) is copied next to the running launcher as `<name>.new` and renamed over the old one (Windows cannot replace a running program, so the old one becomes `<name>.old`, removed at the next start). A launcher inside an app bundle (`X.app/Contents/MacOS`) gets the image's whole `OpenSOW.app` instead: copied beside the old bundle with `ditto`, then renamed over it (`X.app.old` in between, removed after), so the bundle's signature stays whole. Then **Restart launcher** starts the new one. Note: run from `target/release`, an update replaces the cargo build outputs there. `opensow-launcher --check-update` prints what the check finds (repository, platform, latest tag, the matching archive and checksum). Tests: version order, the API answer and the platform's asset (`the_release_brings_this_platforms_archive`), SHA-256 reference values, a whole install from a real `.tar.gz` in a temp folder (wrong hash = nothing replaced), and on macOS from a real `.dmg` made with `hdiutil` (`install_replaces_the_app_from_a_disk_image`: the bundle replaced as a whole, a plain folder gets the programs, the `Applications` link not followed). Not verified yet: a download from a real release (there is none).

## Files
- `launcher.cfg` in the per-user data folder (`~/Library/Application Support/OpenSOW`, `%APPDATA%\OpenSOW`, `~/.local/share/opensow`, or `$OPENSOW_SAVE_DIR`): `language=CZ`, `original=/path`, `warmonger=/path`, `check_updates=0` (only when off), one per line, unknown lines ignored; saved at once. Lookup order in the game (`GameDir::locate`): `OPENSOW_GAME_DIR` / `OPENSOW_WARMONGER_DIR`, then `launcher.cfg`, then the default Steam places (above) / sibling folder.
- The game opens its settings in its **current directory** (`State of War_1.cfg`, the exe's own file, and `opensow.cfg`, this port's switches). Play starts `opensow-game` (from the launcher binary's folder) **in the per-user data folder**, and the Settings page reads and writes those two files there, at once on every change. `opensow.cfg` lines the launcher does not know are kept.
**Differs from the exe:** the exe's settings file sits in the exe's folder (its current directory). Started from the launcher, OpenSOW's copy lives in the per-user data folder, and the install is never written to (docs/config.md). The list of switches (`settings::EXTRAS`) mirrors the game's `options::Extra` / `OWN_ROWS`: keep them in step.

## Look
The page is laid out in logical units 600 high and as wide as the window's shape allows (at least 800; a narrower window shows it smaller with bands) and scaled to fit. Text uses a system font (Arial Unicode on macOS, for the Chinese names; Arial Bold for titles where it has the glyphs; Segoe UI / Arial on Windows; Noto Sans, DejaVu Sans or Liberation Sans on Linux). The fonts are a list of preferred files (`FONTS`, `BOLD_FONTS` in `ui.rs`); `opensow_formats::sysfont::find` takes each at its listed path or, when it is not there, by its file name anywhere in the font folders (Linux: `$XDG_DATA_HOME/fonts`, `~/.fonts`, `<XDG_DATA_DIRS>/fonts`, i.e. `/usr/share/fonts` with Fedora's per-package folders; macOS: `~/Library/Fonts`, `/Library/Fonts`, `/System/Library/Fonts`; Windows: `%WINDIR%\Fonts`, `%LOCALAPPDATA%\Microsoft\Windows\Fonts`; four folder levels deep, read once per run). With none of the listed files, any plain sans-serif face is used (`sysfont::any_sans`: "sans" in the name, no bold/italic/mono/condensed/serif), e.g. Fedora Workstation's variable `NotoSans[wght].ttf`; with no font at all the launcher draws no text. (Not in the exe.) every text exists in the five languages and switches the moment a language is clicked. Long texts shrink, wrap or are cut with an ellipsis (paths from the start).

The icon is the application icon (`art/icon.png`, the pixel-art factory, docs/release.md "Icons"), at its 64x64 pixels from build.rs (`ui::ICON_RGBA`): shown in the sidebar header and on the home page and set as the window icon (Windows/Linux; macOS shows the bundle's); `opensow-launcher --icon-png out.png --size 256` renders it on a checker. The other icons (house, gear, tick, cross), the flags and the Settings backdrop (contour lines of a made-up height field plus a grid) are drawn in code.

### Motion
Animations (not in the exe), all short and eased (`App::tween`, ease-out):
- **Opening:** the window waits a moment (it takes macOS a little to show it), then the sidebar fades in and the page's content fades in from top to bottom while rising 14 units into place over the still picture (about 1 s in all, `FadeKind::Intro`).
- **Another page or settings tab:** the old page fades out while the new content rises 10 units into place, top rows first (0.3 s plus 0.12 s from top to bottom, `FadeKind::Page`); only what the page draws over its picture moves, the picture stays. The sidebar's highlight and accent bar slide to the new entry and the tab's underline slides to the new tab (0.3 s).
- **Language, and the home card when an update is found:** a plain cross-fade (0.22 s, `FadeKind::Swap`).
- **Hover** (0.16 s in and out): the settings gear spins (speeding up and slowing down; it also turns a quarter when Settings opens), the house hops up, game badges grow a little, sidebar labels lean right, the home page's game rows slide their arrow towards the page, a band of light sweeps once across Play and Install as they rise with a deeper shadow, the other buttons rise a little, links lean right and turn gold, stepper arrows nudge the way they step, colours ease.
- **Switches** slide their knob with the track's colour following; language chips fade to gold; a new message slides up and fades in; the download bar moves smoothly; the update badge pops in with a small overshoot, then pulses (What's new).

The window draws 60 frames a second only while something moves (frames keep their rhythm: each is due one interval after the last was due), 30 while only the badge pulses, and none otherwise (`App::frame_interval`). A transition frame at 2000x1240 takes about 10 ms. A value seen for the first time starts at its target, so headless screenshots show the resting state; `animations_run_only_while_something_moves` checks that the launcher goes still and that the finished frame equals one drawn without animation.

### Pictures
`crates/opensow-launcher/art/{home,original,warmonger}.jpg` (1350x900, embedded with `include_bytes!`) are screenshots of real games of this port: the computer playing both sides (`--skirmish MAP --spectate --difficulty brutal`, deterministic). Many games were sampled with `--report` (every 6000 / 2000 ticks on all eight maps), each moment scored by a small script for the best view (both armies close together, bases and an Advancer in it), and the best ones rendered again at 1600x1000 with `--center CX,CY` on that spot. The crop (x 96..1446, y 40..940) leaves out every part of the interface: credits bar, air-strike buttons, minimap, tabs and message lines. Home = 07-Cross of Fire, tick 56040, cell (37,20) (a river, an Advancer's beam, both bases); State of War = 02-Ice Blizzard, 62040, (37,15) (bombers, a fighter, a carryall and burning buildings); Warmonger = 08-Island of Fate, 56040, (37,32) (two armies meeting in the desert). They are the one exception to "no derived images in the repo" (`.gitignore` lets them and the application icon through). At run time each is graded (`grade`: home cool and muted, State of War cold blue, Warmonger red with harder contrast), covers the content area and is darkened towards the bottom, top and left where text sits; the result is cached per page and window size.
